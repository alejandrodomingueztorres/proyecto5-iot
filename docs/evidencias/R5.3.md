### P3.3 — Estado retenido · Intento 1

| Campo | Valor |
|---|---|
| Requerimiento | R5.3 |
| Ejecutada por | Santiago Osorio (Rol 2) |
| Fecha y hora | 2026-11-08 13:44 |
| Entorno | VM Azure `vm-iot-backend` · commit `b7f0f67` · Mosquitto 2.0.20 con `persistence true` |
| Precondiciones | dev01 y dev02 de Balena conectados y publicando (el simulador publica `online` retenido al conectarse) |

**Qué se probó:** Que un suscriptor que llega **después** recibe de inmediato el último estado de cada dispositivo.

**Cómo (pasos y comandos exactos):** en la VM, desde `~/proyecto5-iot/backend`, con
`mqtt()` como en [R5.2.md](R5.2.md):

1. Confirmar que dev01 está publicando:

```bash
mqtt mosquitto_sub -h 68.211.147.97 -p 8883 --cafile /certs/ca.crt -u nodered -P "$MQTT_NODERED_PASSWORD" -t 'iot/dev01/+' -v -W 8
```

2. Abrir un suscriptor **nuevo** a `iot/+/status`, mostrando la bandera de retenido (`%r`) y el
tiempo de llegada desde que se lanzó:

```bash
mqtt mosquitto_sub -h 68.211.147.97 -p 8883 --cafile /certs/ca.crt -u nodered -P "$MQTT_NODERED_PASSWORD" -t 'iot/+/status' -v -F '%r %t %p' -W 3
```

**Resultado esperado:** Llega de inmediato el último estado (mensaje retenido).

**Resultado obtenido:**

```
(1) iot/dev01/temperatura {"device_id": "dev01", "sensor": "temperatura", "value": 22.5, "unit": "C", "ts": "2026-11-08T18:44:44Z"}
    iot/dev01/humedad {"device_id": "dev01", "sensor": "humedad", "value": 69.2, "unit": "%", "ts": "2026-11-08T18:44:44Z"}
(2) 0.51 s  retenido=1  iot/dev02/status online
    0.52 s  retenido=1  iot/dev01/status online
```

**Mediciones:** El estado llegó a los 0,5 s de lanzar el suscriptor, lo que incluye arrancar el
contenedor del cliente y el handshake TLS; no hubo que esperar ninguna publicación nueva.

**Captura:** Sin captura de pantalla; evidencia por salida de la terminal.

**Veredicto:** ✅ Pasa

**Observaciones:** La bandera `retenido=1` confirma que el broker entregó el mensaje guardado y
no uno publicado en ese momento. Como Mosquitto tiene `persistence true`, el estado retenido
también sobrevive a un reinicio del broker o de la VM.
